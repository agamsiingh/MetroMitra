| ADR-035 | M3 routing (`metro_core/routing`): Dijkstra over a graph of stop *visits* `(service, position)` plus per-station "arrive" and "depart" hubs; node pairs "fresh/rode" stop a rider alighting or changing without having ridden, so no interchange walk can be dodged. Four profiles (fastest, easiest, lessWalking, fewestStops) = lexicographic (time, changes, walk, stops) orders; identical routes merged and tagged; alternatives > 1.5 x fastest + 10 min dropped; all ties broken by input-independent order (tested with shuffled rows). An interchange exists only if the dataset has a `transfer` row, the same line has several services, or `through_service_of` says so. **Travel-time fallback** (`TravelTimeModel`, id `fallback-v1`): dataset `travel_s` / `walk_s` / `walk_m` always win; only NULLs are replaced by 35 km/h + 25 s dwell per hop, 180 s boarding wait, 240 s / 200 m interchange walk. These are generic placeholders, **not measurements**: every itinerary lists the `assumptions` it used and the model id, the UI must show "approximate", and the pipeline report marks the model `unapproved-placeholder` | Real open data has no travel times, headways or walk times (ADR-028); routing still has to rank routes offline without inventing source data | Owner approves parameters, or real `travel_s`/headway data is licensed |
| ADR-036 | A station visited twice by one service (Pink Line, Maujpur-Babarpur) is a **seam**: the rider must change there (`TransferKind.repeatedStop`, warning `repeatedStopChange`, estimated walk); a ride may start, end or continue from a fresh boarding there but never pass through. Services with repeated stations (and loops) claim no "towards" terminal. Evidence: en.wikipedia.org/wiki/Pink_Line_(Delhi_Metro) (circular main line + branch, Maujpur-Babarpur common interchange, separate branch services; reference only). The `service-revisits-station` conflict is resolved in the overlay with that reason. Cost of the conservatism: a rider crossing the seam from one ring side to the other is shown a change that may not exist | Never assume a train continues when the data does not say so; supersedes the "routing must handle it" note of ADR-033 | Operator timetable data shows through running at the seam |
| ADR-037 | M3 fares (`FareEngine`) use dataset fare data only; no default exists. Per ticket: exact `fare_override` (from, to, day type) else the half-open slab (ADR-025) for the **shortest distance inside that operator's own network** (sum of edge metres, derived/haversine => confidence `derived`); an override is `verified`. Discounts of the requested media are summed (percent of the listed fare, cap 100), off-peak windows need a known minute of day (otherwise skipped and noted), result rounded half up to whole paise with integer arithmetic. Tickets split at operator changes and at `requires_exit` walks (`separateTicket`). No fare system / no slab / no distance / unreadable window => `unavailable` (or `partial` with no total) | docs/routing.md; DMRC fare tables are not openly licensed (ADR-011), so the real dataset has no fare rows and quotes say "unavailable" | Licensed or owner-verified fare table supplied |

| ADR-041 | M4 search ranking: tiers **exact official name (1000) > exact alias / old name / misspelling / landmark / station code (900) > name prefix (800) > alias prefix (700) > name substring (600) > alias substring (500) > fuzzy (400 name / 350 alias minus 50 per edit)**. Inside a tier: closeness bonus (< 50, shorter remaining text first), then popularity, shorter name, kind (station before line), English name, id. Popularity is a tie-break only and never lifts a lower tier (supersedes the additive popularity/recents idea in the original search.md; recents/favourites/nearest are app-layer, M5). Prefix = text starts with the query or each query word starts the corresponding leading word; substring from 3 characters, or every query word starts a different word in any order; fuzzy allows 0 edits below 4 characters, 1 for 4-7, 2 from 8 (restricted Damerau-Levenshtein on code points), also on a phonetic skeleton, on a leading part of a longer name (>= 8 chars) and on one word of a longer name (scored one edit worse); equal-apart-from-spacing counts as fuzzy with 0 edits. One result per station (its best match); stations and lines share one list | The owner's required order (alias before prefix) differs from the first draft of search.md; bands never overlap so order is predictable and testable | Real-usage evidence that another order works better |
| ADR-042 | Normalisation is shared by index and query and needs no Unicode package: fold Latin diacritics, drop `.` and apostrophes (joins "A.I.I.M.S." -> "aiims"), other punctuation -> space, lower-case, Devanagari nukta removed (precomposed U+0958..095F mapped to base letters), chandrabindu -> anusvara, ZWJ/ZWNJ/soft hyphen dropped, Devanagari digits -> ASCII, a trailing roman numeral -> digit ("Mayur Vihar - I" = "mayur vihar 1"). Abbreviations (`sec`, `stn`, `chk`, `ph`, `mkt`, `intl`) and stop-words (`metro`, `station`, `stn`) are language-level defaults in `SearchConfig`, overridable by optional dataset `meta` keys `search_abbreviations` / `search_stop_words`; they contain no station, line or place name. Stop-words are never allowed to empty a query. Queries are cut at 100 characters | Deterministic, offline, no dependency; docs/search.md wanted the tables outside code | Need for full NFC/NFKC |
| ADR-043 | Cross-script matching: a Hindi query can find a station with no Hindi name (and vice versa) through a Latin *skeleton* of Devanagari (table transliteration + simple schwa deletion) compared with the phonetic key of Latin text (`aa->a, ee->i, oo->u, w->v, ph->f, z->j, au/ow/ou->o`, h after consonant dropped, doubles collapsed; skeletons shorter than 3 characters never match fuzzily). The skeleton is used only to compare: it is never stored, shown or written to the dataset, results copy dataset values, and a missing `name_hi` stays NULL. Matches via the skeleton are flagged `phonetic` and rank in the fuzzy tier | "Rajeev Chok" and the Hindi spelling of a name must work without inventing Hindi names or aliases | Native-speaker review (M13) |
| ADR-044 | Station codes (`station_line.station_code`) are matched on folded text with all spaces removed and no abbreviation expansion (code "PH" stays "ph"): exact (alias tier) and prefix only, never substring or fuzzy; one station is one result even if several lines share a code. Line `short_name` is an alias-class exact value | Codes are identifiers, not words | - |

### Logo risk (needs owner decision before any store listing)
The supplied logo contains two elements that resemble third-party marks:
1. The small red roundel on the train nose looks like the DMRC logo (design-system.md already requires removing it).
2. The large red ring crossed by a navy bar closely resembles the London Underground roundel (TfL trademark).
It is used as-is in M0 because the owner asked for it. Recommended: before release, commission a variant without the nose roundel and without the ring-and-bar composition (or have an IP lawyer clear it).
