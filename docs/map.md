# Metro map

## Goal
Usable, fully offline, legally clean map that can **highlight routes** and **tap stations**.
→ Vector network map generated from our own dataset. No raster maps from DMRC or third
parties; no Google Maps; no basemap tiles in V1.

## Two geometries, one dataset
| Geometry | Table | Used by |
|---|---|---|
| **Schematic** (diagram-style, clean angles) | `map_line_path`, `station.map_x/map_y`, `map_label` | Map tab, route highlight |
| **Geographic** (true lat/lng, simplified) | `geo_line_path`, `station.lat/lng` | Nearby mini-map, "you are here" |

Both ship inside `metro.sqlite`, so the map updates with every data update — no app release needed.

## Generation (tools/data_pipeline `derive` step)
1. Input: OSM route geometry + station coordinates (ODbL) after curated overrides.
2. Project to a local metric plane (equirectangular around Delhi centroid).
3. **V1 layout:** simplified geographic (Douglas–Peucker), parallel-line offsetting where
   services share track, collision-checked label placement with manual overrides in
   `data/curated/map_overrides.yaml`.
4. **V1.1 option:** octilinear schematic via an open-source schematization tool
   (evaluate LOOM / `octi`, University of Freiburg; tool licence does not apply to our output — confirm in M6).
5. Emit normalized coordinates (0–10 000 grid) + label anchors + `zoom_min` per label.
6. Validation: every station has a position; no two station markers overlap at max zoom;
   every service path passes through its stations in order.

## Rendering (app/features/map)
- `CustomPainter` inside `InteractiveViewer` (pan, pinch, double-tap zoom, a11y zoom buttons).
- Paths pre-built into `ui.Path` objects once per snapshot; repaint boundaries per layer
  (lines, stations, labels, highlight).
- Level of detail: interchange labels always; other labels by `zoom_min`.
- Route highlight: non-route layers at 25 % opacity; route legs in line colour, thicker; start/end pins.
- Hit-testing: uniform grid index from `metro_core/map` → nearest station within 24 dp.
- Semantics: invisible list of stations for TalkBack ("Map has N stations, use search").
- Dark palette variant; line colours brightened for contrast.
- Corner attribution: "© OpenStreetMap contributors" → tap opens licences.

## Nearby mini-map
Geographic geometry, user dot, accuracy circle, nearest stations. No basemap.
"Directions" → external maps app via `geo:`/https intent (no API key, no data copied).

## Future
Optional online basemap (MapLibre + a commercial tile provider such as MapTiler/Stadia with
proper licence) for street context — V2, behind a feature flag. Never OSM's public tile servers.

## Implemented in M7 (ADR-055..057)
- **What exists:** the geographic network map from the dataset's station coordinates and consecutive service stops;
  tap -> station detail; route highlight; framing; zoom buttons; error states. Code: `metro_core/lib/src/map/map_geometry.dart`,
  `app/lib/features/map/*`.
- **Deviations from the plan above (deliberate):** no pipeline `derive` layout step and no `map_line_path` tables yet
  (the dataset has none), no schematic layout, no `InteractiveViewer`, no `zoom_min` label levels (labels are chosen by zoom
  and de-overlapped greedily), no dark-palette brightening, no TalkBack per-station list (the canvas has one summary label;
  search is the accessible path), attribution = the dataset's `attribution` meta (OSM text is shown only if the dataset says it).
- **Manual device check:** see docs/device-check.md.

## Added 2026-10-12 (map functions)
- Bilingual labels: the station name in the app language with the other script below (dataset names only); all
  stations are labelled from zoom 3.5, greedily without overlap (route ends, found station and nearest station first).
- Station search on the map (app bar): the M4 search index (English, Hindi, aliases, codes, typos); the result is framed
  and ringed.
- Live tracking (location button): continuous position from `LocationSource.watch()` (10 m filter), blue dot with
  accuracy halo, nearest open station within 30 km (straight line) with distance; tap opens it. Permission denied /
  permanently denied / location off / lost signal each have a state; the map keeps working. Memory only; stops when
  switched off, when another tab is shown, or when the map closes.
- Route distance on results: sum of ridden edges, labelled an estimate unless every edge is official/verified.
- Dense-network markers (2026-10-07): plain stations become dots at whole-network zoom.

## Exported map files (2026-10-12)
`map/MetroMitra_map.svg|png|pdf` are generated by `python tools/export_map.py [dataset.sqlite] [out.svg]` from a built
dataset (stations, lines, colours, English + Hindi names, stop order; nothing from third-party artwork), then
`chrome --headless --screenshot / --print-to-pdf` for PNG / PDF (Chrome shapes the Devanagari text). Credit line:
OpenStreetMap (ODbL), Wikidata (CC0), "not affiliated with DMRC", dataset version and stage. Made from the draft
dataset, so the title says "draft data, not verified"; regenerate after each dataset change. They are **not bundled in
the app**: the app's own map draws the same data live and stays current after dataset updates; a static copy would go
stale and put station names in an asset.
`map/personal-dmrc-based/MetroMitra_Map.pdf` is a DMRC map with a MetroMitra title bar (owner's file): not for the app or
any release, see docs/known-issues.md.

## Overview map (2026-10-12)
`features/map/presentation/overview_map.dart` (Map tab, first app-bar icon): the whole network as one zoomable poster
drawn **live from the dataset** (lines in dataset colours, every station named in both scripts, greedy label placement
with eight positions, legend, credit, "not to scale"). Fits the screen first, pinch to zoom. Same layout rules as
`tools/export_map.py`, so the exported `map/MetroMitra_map.*` and the in-app view agree. No static image is bundled for it.
Tests: `test/overview_map_test.dart` (every station ringed and labelled, no overlapping labels, legend, bilingual text).
Emulator: renders all 244 stations; first show fits the screen (before this fix it opened at 100 % showing one corner).
